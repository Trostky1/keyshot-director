# KeyShot materials and geometric displacement: deep dive

## Objective

Turn imported PBR folders into predictable, editable KeyShot material graphs, with particular attention to real mesh displacement from Poliigon height maps. Keep the imported files intact, expose actual KeyShot controls through the bridge, and tell the user which steps still require choosing the target product part.

## Current finding

**The installed scripting layer exposes graph creation and geometry execution, and the bridge has a guarded path for both.** A controlled KeyShot Studio 2026.2 run used a disposable 100 mm UV-mapped plane and an explicit Texture Map → Displace → root Geometry graph. On this fixture, assigning the graph changed the scene from 3,656 to 822,656 triangles and moved the plane bounds before the bridge called `executeGeometryNodes()`. The explicit call then succeeded but did not further change the measured bounds or triangle count. This confirms live geometric reevaluation for this synthetic graph, not for every material or object type. The original scene was restored from a saved checkpoint.

This is distinct from Normal and Bump. Normal/Bump changes shading; a connected Displace geometry node changes the evaluated mesh surface. KeyShot describes geometry nodes as non-destructive, but warns that they require an explicit execution step, hard edges split, Render NURBS mode does not support them, and dense displacement can make scenes heavier to open. See [KeyShot Displace](https://manual.keyshot.com/keyshot11/manual/materials/material-graph/material-graph-nodes/geometry-node-types/displace/), [Geometry Node Types](https://manual.keyshot.com/manual/materials/material-graph/material-graph-nodes/geometry-node-types/), and the [2026 Material Graph Nodes reference](https://manuals.keyshot.com/kss2026/en-us/manual/material-graph-nodes.html).

In our 2026.2 fixture, assigning the material reevaluated the mesh before the explicit call; the explicit operation succeeded without further measured change.

The source script and this matrix separate three different things: a native parameter exists, Director has code that sets it, and the live renderer produces the intended result. Only the last one establishes a working end-to-end material recipe.

### Documented by KeyShot and Poliigon

- A KeyShot material graph’s nodes only affect the material when connected to the root. The Displace map goes to the Displace node’s `displace` input; Displace goes to root `geometry`.
- KeyShot’s Displacement Height controls the bright end of the map. Its zero-height value/Offset determines where the low end sits. Triangle Size controls mesh resolution, and Maximum Triangles is a target rather than a guaranteed hard cap.
- Poliigon’s current PBR specification identifies displacement as single-channel, 16-bit TIFF/EXR, raw/linear data. Light values represent raised areas and dark values represent lowered areas; mid-gray is the flat surface midpoint. Poliigon notes that its height maps are not normalized to a shared visible contrast, so one arbitrary millimeter value cannot suit every asset. See [Poliigon Materials Explained](https://help.poliigon.com/en/articles/9612755-poliigon-materials-explained).
- Poliigon also documents multiple texture physical-size families (commonly 30 cm and 2.5 m, plus 24 m facade assets) and publishes texel-density guidance. Thus the same UV scale and displacement height do not produce the same physical surface on every asset or model. The folder or MaterialX metadata must inform mapping; guessing a universal tile size is not reliable.

## A reliable Poliigon-to-KeyShot route

1. Import the complete downloaded folder at one chosen resolution. Preserve every original file; classify each map using both its filename and image header metadata. Recent naming uses `Poliigon_<Asset>_<ID>_<Map>`. Older names such as `DISP16`, `NRM16`, and `BUMP16` also appear and must be recognized.
2. Treat Base Color as intended sRGB and displacement, AO, Metallic, Roughness, and Normal as intended raw/linear data. The tested KeyShot 2026.2 Texture Map path applied a square transfer to synthetic grayscale 8-bit and 16-bit inputs, and toggling embedded-profile use did not correct it. This is not proof for vendor EXR/TIFF variants; validate each source family before claiming linear data. Poliigon normal maps use OpenGL orientation; do not invert a normal map or apply a blanket green-channel flip without a render comparison.
3. Build a separate Director material. Connect Base Color, Roughness, Metallic where the selected shader supports it, and one Normal-or-Bump map. Blend AO into Base Color when both are present. Do not claim the graph reproduces a full MaterialX recipe: layered metal/labels, opacity, ORM channel splitting, and arbitrary MaterialX graphs remain separate capability work.
4. For displacement, connect the map to a Displace node and that node to root `geometry`; preserve the original file. Height is stored in native meters from the UI millimeter value. A known 16-bit value x produced decoded input x² in the tested TIFF path. At 0.03 mm, stored 0.5 plus offset 0.5 displaced the test plane by -0.0075 mm; offset 0 displaced it by +0.0075 mm. A derived 16-bit value sqrt(0.5) produced near-zero displacement, but do not apply this transform blindly to vendor maps. `texture_use_profile` on/off did not change the tested result, and the inspected Color Adjust node had no Gamma parameter. Until a supported linearization control is verified, label this path uncalibrated for raw vendor data.
5. Save the material into the Director library and as a KMP, unassigned. Applying it to a part can immediately trigger KeyShot geometry reevaluation: that occurred before the explicit call in the 2026.2 fixture. The bridge still requires exactly one visible, unlocked geometry, validates the root `Geometry` branch and refuses heights above 0.1 mm before its graph-scoped `executeGeometryNodes()` call. Root `Label` bump/opacity and root `Surface` bump are not substitutes for geometry displacement.
6. Review a bounded viewport preview. If displacement is too subtle or too aggressive, adjust the explicit height/offset and compare with the same camera and lighting. Use a representative curved and planar part to distinguish mapping distortion from insufficient mesh tessellation.

## What changed in Director this pass

- Added a separate 0–2× environment-fill multiplier in Studio lighting. Zero maps to a tiny positive native value to keep KeyShot’s environment setter well-defined; it does not change direct light power, exposure, or visible backdrop color.
- Replaced the broken texture-map graph operation. The previous bridge file defined a differently named, incomplete function with unresolved names and conditionally omitted the registered `material_texture_apply` action. The new bridge builder validates imported-file paths and channels, builds the planned Generic/Plastic surface, wires supported maps and AO Multiply, and adds the actual Displace graph branch.
- Added the explicit `execute_material_geometry` agent action, backed by the installed `MaterialGraph.executeGeometryNodes()` method. It requires exactly one assigned object and refuses unassigned, shared, hidden, or locked geometry.
- Added image-header dimensions, channels and bit depth to new texture-set imports and bounded lazy metadata reads for older imported files where the PNG/JPEG/TIFF/EXR/HDR header supports them. This enables the agent to distinguish a 16-bit displacement source from a display preview without decoding whole images.
- Recognized the legacy `DISP16`, `NRM16` and `BUMP16` suffixes. Raised the aggregate texture-set limit to 512 MB while retaining the existing 80 MB per-file limit; aligned the folder importer’s file-count message with the bridge’s 24-file cap.
- Added a single-part guard around geometry execution; if the same material is assigned to multiple parts, or its only part is hidden/locked, the bridge refuses to execute.
- Added a topology preflight: only a single Displace node connected to root `Geometry` with a connected height input can execute. Label and surface bump/opacity branches are kept out of the geometry decision. Texture-set displacement now defaults to 0.01 mm and accepts 0.001–0.1 mm.
- Matched material-part discovery and copy operations to the installed KeyShot representation observed in `PluginTest.bip`: NURBS geometry IDs can be exposed as scene-tree Groups (`isObject() == false`) while still appearing in `lux.getObjects()`. The Material Lab now uses that geometry-ID set to list and target those parts.
- Added REA-backed notes on the installed Texture Map mapping controls. Disposable live calibration verified mapping value 4 against authored UVs and measured scale, shift, and angle effects; the builder still leaves defaults alone because non-UV fallbacks and per-asset physical scale are unresolved.

## Current limits and unresolved questions

- **The user's library graphs remain uninspected.** This disposable run used synthetic graphs only. The Advanced Plastic screenshot establishes separate Label and Geometry branches, but the exact Plastic Realistic edges and current height values still need read-only graph inspection.
- **Mapping is only partly calibrated.** Mapping value 4 followed authored UVs on the test mesh. The builder currently leaves mapping defaults alone; do not switch globally without UV detection or a fallback. Physical texture scale and compatibility with non-UV meshes or other projections remain open.
- **Raw/linear data interpretation remains a blocker.** Synthetic 8-bit PNG and 16-bit TIFF values were squared in the tested graph. The embedded-profile toggle did not change that transfer, and the live Texture Map/Color Adjust controls exposed no verified gamma correction. Do not describe the direct data-map path as linear until a safe correction is implemented and verified against real vendor maps.
- **Height and sampling evidence is fixture-specific.** The 0.01, 0.03 and 0.1 mm bounds scaled linearly, and doubling the native resolution value roughly halved triangles. Test on representative product meshes and map families before choosing per-asset settings. Material assignment itself caused tessellation in this 2026.2 scene; the explicit execution call did not add a further measured change.
- **Execution scope is material-scoped.** KeyShot exposes graph-scoped execution, not a selected-object execution call. The bridge now refuses shared assignment and reports the parts that need separate materials. Use a fresh, single-part material for a controlled first benchmark.
- **Advanced graphs are not interchangeable.** The observed `Advanced Plastic #2` template contains procedural and raytraced branches. Copying its Curvature-to-Displace connection may violate KeyShot’s documented geometry-node restrictions. Keep that recipe opt-in and validate the exact graph in KeyShot before calling it production-ready.
- Unsupported or deferred channels include Specular, ORM splitting, BaseColorOpacity/Opacity, sheen, transmission, emission, layered metal/plastic labels, physically calibrated Mapping 2D tiling, and general MaterialX translation.
