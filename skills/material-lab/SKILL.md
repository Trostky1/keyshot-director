# Material Lab workflow

Use this playbook for reference-photo-to-material requests and material questions in the dedicated Material Lab.

## Read the reference

1. The user may attach up to 8 reference images. Treat them as one evidence pack for the current prompt: compare cues across all images, identify agreement/conflict, and synthesize a consistent target rather than treating each image as a separate request.
2. Distinguish image roles when possible: different angles corroborate a finish, close-ups reveal texture scale and direction, and map sheets may encode base color/albedo, roughness, bump/height, normal or specular. Do not assume a photo is a map (or a map is a photo) without evidence; describe uncertain roles as hypotheses.
3. Separate visible surface cues from lighting and environment cues. Describe base hue, value, gloss/roughness, apparent texture scale, directionality, transparency, metallic response and edge behavior only when visible. A bright highlight does not uniquely reveal roughness; warm illumination does not prove a warm base color. State uncertainty briefly when it matters.
4. The reference pack is transient context for this prompt, not a persistent training dataset. Do not imply it trains or fine-tunes the model.
5. Turn the request into an achievable specification before acting. For a requested variation of a KeyShot library material, use the Material Lab copy workflow when the user has selected a source and target part. Otherwise default to a new reusable material.

## Choose the right material workflow

There are two different jobs here. Keep them separate so a generic recipe does not overwrite a good material:

1. **Recreate a Poliigon asset from its downloaded folder.** Treat the folder as the source of truth. Inventory every map and its filename, dimensions, bit depth, and likely role before building anything. Use names as clues, not proof; check channel previews and compare related maps. Preserve the original folder. Do not substitute an image-prompted color or procedural noise for a supplied map.
2. **Create a material from a visual reference.** This is an authored approximation, not a texture-folder conversion. Keep a known-good result as the starting point when one exists. Make an independent copy and change one property at a time; compare renders with the same part, camera, lighting, and exposure. Do not regenerate or “improve” a successful plastic from scratch just because more general material notes are available.

For the Poliigon route, first ask whether the user downloaded for KeyShot and which KeyShot version is in use when that affects available map variants or shader features. Poliigon's current guide recommends a suitable material type (it uses Advanced for graph-based setup), a shared Mapping 2D node when all texture maps need consistent tiling, and connecting each map to its intended socket. Its normal-map orientation and layered metalness/displacement examples are version- and graph-specific. Director selects Generic for PBR texture sets or sets with a Metallic map, and Plastic only when the asset name explicitly indicates plastic/rubber/resin/vinyl and no Metallic map is present. It wires Base Color, Roughness, Metallic on Generic, and Normal/Bump only where the selected shader exposes the socket. By default, builds include AO Multiply blending and a bounded Displace geometry node at 0.1 mm whenever those maps are present, even if source MaterialX strengths are zero; users can explicitly omit either map. Labels/layers, specular and shared mapping are not yet built. Do not imply this recreates a full Poliigon graph.

When a MaterialX inventory names source images that are absent from the imported texture set, identify the missing filenames and have the user drop the same complete folder again. Director resumes an unfinished matching set. Do not offer to build a Base Color-only starter as the default response to a partial import. A partial build is available only when the user explicitly requests the available maps despite the missing files. A MaterialX AO_Mix_Strength or displacement scale of 0 means that channel is disabled in that source recipe, but Director's default build enables AO and displacement when those maps are present unless the user explicitly asks to omit them.

Classify roughness versus gloss explicitly. Only invert a map when folder naming, documentation, or channel inspection identifies it as glossiness; never invert a normal map. Treat color maps as color and scalar/vector maps as data. Check the target model's UVs and physical scale before judging detail size. A shared mapping adjustment must keep all related maps aligned. Do not apply a blanket “negative normal” rule: verify orientation on a small preview because normal conventions and shader setup can differ.

When a material looks worse after adding information, stop adding parameters. Restore the last good independent copy or use material undo, lock the camera/light/exposure, then compare one controlled change at a time. Prioritize visible evidence (same-view renders and map previews) over a more elaborate node graph. A tutorial recipe is a starting hypothesis, not evidence that it matches this asset, shader, KeyShot version, or lighting setup.

## Texture-editing method

Use a conversational, intent-first workflow: understand what the user wants the surface to look like, identify the relevant map/channel, then make the smallest supported change on an independent copy. Do not send the user back to manual “tune” controls for work the assistant can safely perform. Keep KeyShot-only controls such as advanced graph rewiring in KeyShot, and be explicit about that boundary.

When evaluating maps, apply these checks before wiring them:

1. Confirm each file's intended role instead of trusting its filename alone. A color/albedo map carries color; roughness, gloss, height, bump, normal, metallic and AO maps encode different data and are not interchangeable. A gloss map may need inversion to become roughness, but do not transform it unless the supported tools can do so and the user has requested it.
2. Treat base color as color data and scalar/vector maps as data. Preserve the user's originals byte-for-byte; perform any future image transformations only on a clearly named derived copy.
3. Judge texture scale and direction against the physical product and reference close-ups. Ask for dimensions or a scale cue when getting scale right materially affects realism; otherwise state the estimate. Avoid adding uniform noise or surface damage merely to make a material look detailed.
4. Keep bump/height, normal, and displacement concepts distinct. Do not claim a normal or height map is displacement, and report whether AO, displacement, metallic or specular was connected or skipped in the actual build.
5. Verify the target shader exposes the relevant input and confirm the result on the independent copy. If a socket or operation is unsupported, explain what was not changed and offer the closest supported path.

For chat-driven edits to an existing look, interpret natural language as a requested visual outcome (for example, “less glossy,” “invert this confirmed gloss map to roughness,” or “soften the horizontal grain”), identify the precise imported map, make a derived map with `edit_texture_map`, and connect it only to an independent material copy using `set_material_bump`. Available deterministic operations: grayscale-map inversion, contrast adjustment, half-image tile offset to expose the seam for manual repair, and one-axis smoothing. Axis smoothing reduces high-frequency detail in that direction; it does not create directional grain. The source map remains unchanged, and derived files are listed within the originating texture set. Editing currently supports non-interlaced 8-bit grayscale PNG up to 16 MP; other formats, color maps, normal maps requiring specialized processing, 16-bit/HDR and arbitrary generative pixel edits must fail clearly without altering the source. Never invert normal maps. Use inversion for gloss→roughness only when the source is confirmed to be glossiness. Report the derived filename and connection/result; do not claim unsupported image generation or arbitrary graph rewiring.

## Current Director capability

- The KeyShot Material Library editor can browse loaded library entries, then create an independent copy on one selected unlocked scene part. The library source stays unchanged. Scene-material copies are also available when the exact part/material pairing has been verified.
- A plain starter material is an unassigned KeyShot Diffuse material, named `Director <descriptive finish>`. For texture sets, the bridge upgrades the fresh Diffuse root to the selected Plastic or Generic shader before connecting maps. Model selection uses the imported set/material name and map roles: a Metallic map selects Generic; otherwise explicit plastic/rubber/resin/vinyl/polymer naming selects Plastic; all other sets default to Generic. This does not inspect the name of a scene object because texture-set builds create unassigned library materials.
- Inspect the graph and current node IDs before editing. The setter changes concrete numeric, boolean or color-array parameters on Director-created materials and on the single scene material explicitly unlocked by the user. Prefer relevant exposed values such as roughness or specular strength; do not invent unsupported node inputs. On a library-copy, the channel editor supports Base Color, Roughness, Bump, and Normal only when the copied shader exposes a direct matching input, plus exposed bump strength.
- Connected shader inputs on source scene and library materials remain protected. In the dedicated KeyShot Material Library editor, choose a loaded library entry and one unlocked scene part; Director makes an independent copy on that part. On that copy, supported imported Base Color, Roughness, Bump, or Normal channels can be wired when its shader exposes the matching direct input; bump strength can also be adjusted when exposed. Other graph inputs remain read-only. The texture-set converter selects a new unassigned Plastic or Generic graph from the asset name and available PBR channels.
- Explain that color and roughness are visual estimates from the reference, and the material is not assigned to the product. The user can drag it onto chosen parts in KeyShot.
- When the user asks for a new/tuned material as the result, save the finished Director material to KeyShot's material library and export a KMP package automatically. Report the package path; the Material Lab assets shelf exposes download and show-folder actions. The material remains unassigned, so the artist can drag it onto chosen parts in KeyShot.
- A saved KMP is a package, not a live graph. Material Lab may match embedded map filenames back to an imported texture set. If a selected package has a confidently matched source set and the user asks to add maps, rebuild from that exact set with the requested channels under a new Director name. Preserve the original KMP and explain that the result is a new package. If no source set is matched, ask the user to select/import the source set or load the material into KeyShot.
- Use the one-step material undo after an edit when needed.
- Texture sets can be imported separately from reference photos. Originals are retained unchanged under `materials/texture-sets/`; filename-based role labels are hints. The converter selects Generic for PBR sets or any Metallic map and Plastic for explicitly plastic/rubber/resin/vinyl-named sets without Metallic. It connects Base Color, Roughness, Metallic on Generic, and Normal/Bump only where the shader exposes a matching input. AO blending and displacement can be explicitly enabled; arbitrary MaterialX graphs remain unwired; zero AO mix or displacement scale in MaterialX means that channel is disabled in the source recipe. An uploaded MaterialX file is parsed only for channel-connection and strength hints, never executed as code or treated as a native KeyShot material.
- A changed image is a new file under its texture set's `derived/` folder, never an overwrite of its imported source. Import that derived file as an alternate map before wiring it. The editing tool currently accepts only grayscale 8-bit non-interlaced PNG; do not resave scalar data as lossy JPEG or silently down-convert high-bit-depth EXR/TIFF/HDR.
- Before using `material/texture-file`, keep each source file and each complete set at or below 80 MB. Never edit, recompress or overwrite the user's originals. Imported sets are visible in Material Lab with an **Open this set** action.

## Boundaries and next implementation targets

Director edits existing looks through independent per-part copies. The library-copy workflow supports Base Color, Roughness, Bump and Normal direct image sockets when exposed by the selected material shader, plus bump strength where available. It does not wire Specular, Metallic, AO, Displacement, layered, glass, label or arbitrary MaterialX nodes. For unsupported channels, report that they were skipped; do not imply they affected the output. KeyShot's documented native material importer does not list MaterialX.

The library-copy editor explicitly targets one unlocked scene object and relies on KeyShot's link=false material assignment to make a separate instance. Scene-copy operations recheck the object's current material before assignment. Never infer that a material is unshared from its name. Do not add automatic apply-to-many behavior. Unsupported shader sockets must fail without changing the source or library entry.

For a newly built texture-set material, supported maps are Base Color, Roughness, Metallic (Generic only), and one Normal-or-Bump map where the chosen shader exposes the matching socket. Roughness is routed through Color To Number when required. AO Multiply blending and bounded displacement geometry are included by default whenever those maps are present; these options override zero strengths from source MaterialX. Displacement defaults to 0.1 mm and requires Execute Geometry after assignment. Specular, layered graphs, shared Mapping 2D nodes and arbitrary MaterialX graphs are not yet implemented. Report skipped maps. Do not claim that the scene object's name determines a texture-set material graph unless a future workflow explicitly inspects a selected scene part.

## Live graph reconnaissance (KeyShot Studio 2026.2, 2026-10-12)

- Through the active in-app bridge, `lux.getMaterialGraph(name)` plus `MaterialGraph.getNodes()`, `ShaderNode.getParameters()`, and input-edge inspection can read real scene graphs without opening the Material Graph UI. A small Director Poliigon plastic graph returned in under 0.1 s and exposed image paths, `normal`, profile/gamma flags, UV mapping values, connected sockets, and scalar/color values. Treat this as runtime observation for the current scene, not a promise that every graph will be equally fast.
- `Advanced Plastic #2` was observed as a 46-node, 22-edge graph. Its root connects a Plastic surface, a Diffuse labels branch, and a Displace geometry branch; procedural nodes include Noise, Scratches, Granite, Spots, Curvature and Color Composite. It has no Texture Map image nodes. The inspected graph connects Curvature into Displace. KeyShot's Geometry Node Types documentation says raytraced textures such as Curvature cannot control Geometry Node parameters, and warns that heavy displacement can make scenes slow to open. Flag this connection as unsupported and a possible load/performance contributor; do not silently flatten or rebuild the source graph.
- The sample Director Poliigon plastic is a much smaller 11-node, 5-edge Plastic graph: Base Color image to Diffuse, Roughness image through Color To Number to Roughness, and Normal image (normal flag enabled) to Bump. The three images point to the imported Poliigon Plastic Mold Dry Blast set. Preserve the successfully tuned material as the starting point when it already looks better than a newly generated approximation.
- Material names are not reliable evidence of shader or map identity. In the observed scene, `Director Realistic Brushed Metal` had a Plastic surface and referenced the same Plastic Mold Dry Blast image set. Inspect the root surface type and actual map paths before claiming that a named material represents that finish; do not alter or rename it without the user's instruction.
- One read-only request that inspected several different scene materials sequentially stalled long enough for the bridge heartbeat to pause temporarily; the specific graph responsible was not isolated. Keep investigations to one selected graph at a time, return compact summaries, and stop if heartbeat freshness is lost. Avoid broad graph sweeps and all preview renders while diagnosing reported GPU problems.
- The Material Library browser currently enumerates `lux.getLibraryMaterials()` on panel startup, after each debounced search change, and again to validate a library-copy action. This can repeat library-list work inside Director; it is a candidate for session caching if the slowdown occurs in Director's browser. It does not establish the cause of a slow native KeyShot material load.
- No GPU-mode switch appears in the inspected Director bridge/server source. KeyShot's manual says GPU memory exhaustion can revert real-time rendering to CPU and the viewport warning icon indicates materials/features that do not display correctly in GPU mode. Treat GPU failure as unconfirmed until the exact dialog/error and scene context are captured; the material graph's Displace/Curvature combination is only a lead, not proof of causation.
- The live bridge confirms KeyShot's exposed `MaterialGraph`, `ShaderNode`, `ShaderParameter`, and `ShaderEdge` APIs can inspect graph node types, values, and connections directly. KeyShot's scripting documentation also describes graph node creation/removal, parameter edits, and edge creation/removal. This gives Director a real graph API for deterministic builders; AI should choose a validated recipe and values rather than inventing arbitrary topology.
- Historical reconnaissance note (superseded for texture-set builds): the earlier `material_texture_apply` path was Plastic-only and did not connect Metallic. The current builder selects Plastic or Generic from the imported set name and map roles, with Metallic connected only on Generic. The existing-material independent-copy editor is still a separate workflow; compare its `texture_use_srgb` handling with the create path before consolidating, and treat that as a consistency check rather than a confirmed color bug.
- The live `Advanced Plastic #2` Curvature-to-Displace edge is connected with displacement resolution 0.00002 m, height -0.00001 m, and a 20-million maximum-triangle setting. KeyShot documentation calls that node connection unsupported and says heavy displacement can slow scene opening. This is a plausible contributor to a slow open, but the live graph alone does not establish causation or explain the reported GPU failure.
